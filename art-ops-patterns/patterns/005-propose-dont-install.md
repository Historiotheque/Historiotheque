# PATTERN-005: Propose, Don't Install

**Context:** Growing the language itself — every new term, pattern, or structural change.

**Problem:** A language written silently, by one hand, in files the operator never approved, becomes a foreign system imposed on the practice. Terms installed without adoption rot: nobody uses them, but they clutter every document.

**Solution:**

1. New terms are proposed explicitly, in conversation, as proposals — never smuggled into a document.
2. The operator adopts or rejects on the spot, in their own words. Rejection is instant; the proposal is dropped the same day.
3. Only adopted terms enter files, in the operator's words, verbatim.
4. Structural changes (new folders, new repos, new numbering) get the same treatment: proposed first, built after approval.

**Worked example:** "Through-bound" — coined by the operator in conversation, adopted on the spot, and only then written into PATTERN-004. Terms installed silently into drafts have always been stripped out on review, at a cost.

**Related:** PATTERN-003 (proposals are staging: adopt or drop — never let them sit).
