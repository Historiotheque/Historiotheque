# PATTERN-002: The Sender Owes Classification

**Context:** Any signal the operation emits — posts, releases, emails, notices.

**Problem:** An unclassified signal exports the work of understanding it onto the receiver. The receiver pays in attention; the sender paid nothing. Cheap to send, costly to receive — the mechanism of every inbox disaster.

**Solution:** No signal leaves the operation unclassified. A well-formed signal states three things: **content** (what it is), **what is wanted** (response? action? nothing?), **time frame** (by when, if ever). Before sending, walk the tree: classifiable? response? urgent? action? — and write the classification into the signal itself, so the receiver never has to mind-read.

**Worked example:** The daily "can we meet today?" email — urgency without a time frame, response and action unseparated — rewritten as: "Request: 20-minute call today before 9pm? Topic: debrief, no decision needed — sounding board only. Reply by 6pm if today works, otherwise tomorrow." Same content, zero mind-reading owed.
