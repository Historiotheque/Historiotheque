# The New Documentation

*The founding charter of the Historiotheque's documentation practice.
Distilled 2026-09-25 from the legacy historiotheque.ca website content
(April–May 2024, archived September 2025).*

## The proposition

The New Documentation is the systematic, public, version-controlled documentation
of an art-research practice — every process logged, every log published, nothing
kept in the dark. It treats the artist's working methods the way open-source
software treats code: transparent, reproducible, and built to be learned from.

## Core principles

1. **Everything gets logged.** Every aspect of the artistic process, from concept
   to completion — ideas, research, experimentation, decisions, failures,
   collaborations.
2. **Posted online.** Documentation lives in public-facing spaces: distributed
   revision control systems, openly accessible to anyone.
3. **Nothing kept in the dark.** Transparency is the default; secrecy is the
   anomaly that must justify itself.
4. **Working in the light.** Integrity, transparency, responsibility, truth, and
   accountability govern what is recorded and what is published.

## The break

The New Documentation departs from the artist's mystique — the older paradigm in
which process was trade secret and persona was enigma. In its place stands the
Open Source Artist: process shared, methods reproducible, knowledge cumulative.
What the open-source movement did for software, this does for art-research.

## The practice

- **Continuous logging:** the work is recorded as it happens, not reconstructed after.
- **Version control:** changes are tracked over time; the evolution of a project is
  itself a document.
- **Documentation standards:** each medium — images, sounds, texts — gets its own
  metadata standards, so the archive stays searchable across decades.
- **Reproducibility:** a documented process can be re-run — by the artist later,
  or by anyone with a web browser.
- **Peer review and feedback:** public documentation invites correction, and the
  practice improves by it.

## What it governs here

In this repository, The New Documentation is implemented as specifications (the
`specs/` folder), procedures (the `procedures/` folder), and the logs, declarations,
and releases they produce. The specs define the instruments; the procedures define
their use; the logs are the evidence.

*The New Documentation is a standing commitment, not a project phase. It has no
end date.*
